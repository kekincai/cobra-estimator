# design/ — 画面設計稿

14 画面ぶんの設計稿（`*.dc.html`）と、画面の並びを決める `canvas.json` を置いている。
見た目・文言・操作はこの設計稿に合わせる（ルートの `CLAUDE.md`）。数値は `IMPLEMENTATION_BRIEF.md` §6 を優先する（設計稿の各画面は説明用に少し違う数字を使っている。42.3・49.1・18.4% など）。

## ファイルの形式

各 `.dc.html` は 1 画面ぶんの自己完結した HTML。

| 部分 | 中身 |
|---|---|
| `<x-dc>` の中 | マークアップとインラインスタイル。`{{x}}` は差し込み、`<sc-for list="{{items}}" as="i">` は繰り返し、`<sc-if value="{{flag}}">` は条件、`style="{{obj}}"` はスタイルの束縛、`onClick="{{fn}}"` はイベント |
| `<helmet><style>` | 画面ごとの CSS（ホバー、アニメーション、`prefers-reduced-motion`） |
| 末尾の `<script type="text/x-dc">` | `class Component extends DCLogic`。React 風の `state` と、テンプレート変数を返す `renderVals()`。`data-props` の `accent` は強調色（既定 `#D4FF4F`） |
| `<body>` 直後のコメント「実装メモ」 | 設計稿に描いていない振る舞い（PR #15 以降）。下の「設計稿にない UI」と同じ内容を画面ごとに書いたもの |

`canvas.json` は画面の一覧・大きさ・グループ（ボードの配置）。

## `support.js` がないこと

各ファイルは `<script src="./support.js">` を読み込むが、`support.js` は**一度もコミットされていない**（`git log --all -- design/support.js` が空）。設計ツール側のランタイムで、`<x-dc>` を描画して `renderVals()` の値を流し込むもの。

- そのため、ブラウザで直接開く（`file://`）と `{{p50}}` や `<sc-for>` がそのまま残った**テンプレートのまま**表示される。壊れているわけではない。
- `support.js` を推測で作らない。読むときはソースを読む：静的な文言と色は `<x-dc>` の中、計算や一覧の中身は `renderVals()` と `constructor` のデータにある。
- `IMPLEMENTATION_BRIEF.md` 冒頭の公開版（claude.ai の artifact）は PR #15 **より前**の設計稿で、下の変更履歴は反映されていない。食い違ったらこのフォルダのファイルが正。

## 色

設計稿は色を 16 進でそのまま書いている。実装では `apps/web/src/index.css` の `@theme static` のトークンを使う。主な対応：

| 設計稿 | トークン | 用途 |
|---|---|---|
| `#0B0D12` / `#13161E` / `#171B25` / `#1B2030` | `bg` / `card` / `card-2` / `raised` | 面 |
| `#222734` / `#3A4257` | `line` / `line-strong` | 線（`line-strong` は文字色に使わない） |
| `#F2F4F8` / `#C7CDD9` | `text` / `body` | 文字 |
| `#98A0B1`（旧 `#8B93A5`） | `sub` | 補足の文字。情報や注意を運ぶ文字はこれ以上の明るさ |
| `#7F889B`（旧 `#5E677A`） | `weak` | いちばん弱い文字（raised 上でも 4.55:1） |
| `#FF7A59` / `#FF9F84` / `#FFB4A0` | `coral` / `coral-soft` / `coral-ink` | 注意・L3・予算超過 |
| `#4A2A22` / `#5A3328` | `coral-line` / `coral-line-strong` | 注意カードの枠 / 関係図の L3 ノードの枠 |
| `#5A6270`（旧 `#9AA1AD` を置き換え） | `ink-sub` | レポート（白地）の補足・軸の端値 |

新しい色を直書きしない。トークンにない色が要るときは `index.css` に足してからこの表にも足す。

## 全画面に共通する決まり（PR #15 以降）

- **文字は 11px 以上**。例外はレポート（印刷用の pt 指定）と、縮んで描かれる散布図・曲線の SVG 目盛り（実績データ・実績の編集・リスク）。
- **P 値の書き方**：主表記は「超過確率」、P 値は補助。「49.9 人月（超過確率 20%・P80）」、中央値は「中央値（超過確率 50%）」。「最悪」「80% の確度」は使わない（三角分布の「最良・最頻・最悪」は専門家の三点見積りの用語なので残す）。実装は `apps/web/src/ui/percentile.ts`。
- **版と実績の言葉を分ける**：実績は「採用 / 除外」、モデルの版は「見積りに使う / 見積りに使用中」。
- **ホバーで浮くのはダッシュボードのタイルだけ**。他の画面のカードは枠の色だけ変わる。
- **読み込み中 / 空 / エラー**：読み込み中に「ありません」と言わない。エラーは日本語の説明と「再試行」。

## 設計稿にない UI（仕様メモ）

全画面のマークアップを描き直すかわりに、仕様をここに書く。実装が正。

- **狭い画面（1024px 未満）の外枠**：左のナビは引き出し（幅 `min(280px, 86vw)`）。上に 52px のバー（「メニューを開く」ボタン・ロゴ・検索ボタン）。開いている間は背面を操作不可にし、Esc・背景クリックで閉じてボタンへフォーカスを戻す。画面を移ったら自動で閉じる。`apps/web/src/ui/Layout.tsx`。
- **検索の入口**：1024px 以上ではロゴの下に「検索 ⌘K」（Mac 以外は「Ctrl K」）、狭い画面では上のバーの虫眼鏡。ダッシュボードの検索ボックスも同じパレットを開く。
- **コマンドパレット**（⌘K / Ctrl+K）：ネイティブ `<dialog>`、幅 640px。入力欄「画面・見積り・要因・実績を検索」、結果は「画面 / 見積り / 変動要因 / 実績データ」の組。↑↓・Enter・Esc。全角・半角、ひらがな・カタカナを区別しない。`ui/CommandPaletteDialog.tsx`、開くのは `ui/commandPalette.ts` の `openCommandPalette()`。
- **確認ダイアログ**：取り消しにくい操作の前に出す（版の切り替え、削除、権限変更、取り込み確定、5 世代目の上書き、申請の承認・却下）。幅 440px、`card` 地・`muted` 枠・角丸 16px、右下に「キャンセル」と確定ボタン（破壊的な操作は coral）。エラーは確定ボタンの上に coral-soft。`ui/ConfirmDialog.tsx`。
- **未保存のまま離れるとき**の確認：要因の編集・要因の追加・実績の編集・見積りの条件・予算。`ui/useUnsavedChangesPrompt.ts`。
- **新しい見積り**：ダッシュボードの「+ 新しい見積り」→ 名前（必須）と予算（任意）のダイアログ → `/estimate/:id`。世代 0 の見積りは条件画面に初期案内を出し、最初の実行で G1 を作る。
- **予算の保存**：ダッシュボードとリスク画面。動かした値が保存値と違うときだけ「予算を保存」「元に戻す」。レポートは保存済みの予算を載せる。
- **申請の確認**（取り込み / 書き出しの 4 つ目のタブ、管理者のみ）：申請一覧と詳細、申請者へのコメント、「承認する / 却下する」。
- **利用者**（`/admin/users`、管理者のみ）：設計稿なし（PR #14）。名前 + メール / 権限 / 操作の 3 列。権限の変更と削除は確認ダイアログ。自分と最後の管理者は変更できない。
- **世代の指定**：`/estimate/:id?gen=G2`、`/risk?gen=G2`、`/report?gen=G2`。条件 / リスク / レポートのタブと各リンクが引き継ぐ。
- **アクセシビリティの外枠**：画面ごとの `<title>`（「変動要因 | Estima」）、移動後に h1 へフォーカス、「メインへスキップ」リンク。
